# מערכת לניהול משימות

מערכת לניהול משימות אישיות, שנבנתה במסגרת תכנית ההתנסות המקצועית בחממת ENTER. המערכת מאפשרת ליצור משימות, לעקוב אחרי ההתקדמות שלהן, לערוך, למחוק ולסנן אותן לפי סטטוס. היא מורכבת משירות API בצד השרת וממשק משתמש בדפדפן, והנתונים נשמרים במסד נתונים כך שהם לא נעלמים ברענון הדף או בהפעלה מחדש של השרת.

## טכנולוגיות

| רכיב         | טכנולוגיה                |
| ------------ | ------------------------ |
| צד שרת       | C#, ASP.NET Core Web API |
| גישה לנתונים | Entity Framework Core    |
| מסד נתונים   | SQLite                   |
| צד לקוח      | HTML, CSS, JavaScript    |
| בדיקות API   | Postman                  |

## הרצת המערכת

דרישות מוקדמות: יש להתקין את .NET SDK בגרסה 10 ואת הכלי של Entity Framework:

```
dotnet tool install --global dotnet-ef
```

יצירת מסד הנתונים, בהרצה הראשונה בלבד:

```
dotnet ef database update
```

הפעלת השרת:

```
dotnet run
```

אחרי ההפעלה, פותחים בדפדפן את הכתובת `http://localhost:5256` ומקבלים את ממשק המשתמש. ה-API זמין באותה כתובת, תחת הנתיב `/api`.

הפקודה `dotnet ef database update` יוצרת את הקובץ `tasks.db` בתיקיית הפרויקט, עם הטבלאות ועם ארבע קטגוריות התחלתיות: לימודים, עבודה, אישי ובית.

## מבנה המערכת

המערכת בנויה משלוש שכבות:

- **צד הלקוח** הוא עמוד HTML אחד, עם קובץ עיצוב וקובץ JavaScript. הוא רץ בדפדפן, ופונה לשרת בבקשות HTTP באמצעות הפונקציה fetch.
- **צד השרת** מקבל את הבקשות, בודק את תקינות הנתונים, מבצע את הפעולה ומחזיר תשובה בפורמט JSON. הוא גם מגיש את קבצי צד הלקוח, ולכן שני החלקים רצים מאותה כתובת.
- **מסד הנתונים** הוא קובץ SQLite עם שתי טבלאות, משימות וקטגוריות. השרת ניגש אליו דרך Entity Framework Core, בלי שאילתות SQL ידניות.

### מבנה הפרויקט

```
TaskManager/
|-- Controllers/
|   |-- TasksController.cs
|   +-- CategoriesController.cs
|-- Models/
|   |-- TaskItem.cs
|   |-- Category.cs
|   +-- Enums.cs
|-- DTOs/
|   |-- CreateTaskDto.cs
|   |-- UpdateTaskDto.cs
|   |-- UpdateStatusDto.cs
|   +-- TaskResponseDto.cs
|-- Data/
|   +-- AppDbContext.cs
|-- Migrations/
|-- wwwroot/
|   |-- index.html
|   |-- style.css
|   +-- app.js
|-- Program.cs
|-- appsettings.json
+-- TaskManager.postman_collection.json
```

- תיקיית **Controllers** מקבלת את בקשות ה-HTTP ומחזירה תשובות.
- תיקיית **Models** מכילה את המחלקות שמייצגות את הטבלאות במסד הנתונים.
- תיקיית **DTOs** מכילה את מבני הנתונים שנשלחים ומתקבלים דרך השרת. הם מפרידים בין מה שהלקוח שולח לבין מה שנשמר במסד, כך שהלקוח לא יכול לקבוע בעצמו שדות כמו המזהה או תאריך היצירה.
- תיקיית **Data** אחראית על החיבור למסד הנתונים ועל נתוני הקטגוריות ההתחלתיים.
- תיקיית **Migrations** נוצרה אוטומטית על ידי Entity Framework, ומתארת את מבנה הטבלאות.
- תיקיית **wwwroot** מכילה את קבצי צד הלקוח.
- הקובץ **Program.cs** מגדיר את השרת ומפעיל אותו.

## ממשק המשתמש

הממשק בנוי כעמוד אחד: מסך ראשי קבוע, ושאר המסכים נפתחים מעליו כחלונות קופצים.

- **המסך הראשי** מציג את המשימות ככרטיסים, עם תגיות של סטטוס, עדיפות, קטגוריה ותאריך יעד. תאריך יעד שעבר מסומן באדום.
- **לשוניות** מסננות את הרשימה לפי סטטוס: הכול, לביצוע, בתהליך והושלמו.
- **חיפוש** מסנן לפי טקסט בכותרת ובתיאור, ו**מיון** מסדר לפי תאריך יעד, עדיפות או תאריך יצירה.
- **תיבת הסימון** בכל כרטיס מסמנת משימה כהושלמה בלחיצה אחת, בלי לפתוח חלון.
- **טופס המשימה** משמש גם ליצירה וגם לעריכה, ומציג הודעת שגיאה ליד השדה כשהכותרת ריקה.
- **חלון הפרטים** נפתח בלחיצה על כרטיס, ומציג את התיאור המלא ואת תאריכי היצירה והעדכון.
- **חלון אישור** מופיע לפני כל מחיקה.

שגיאות מהשרת, וגם מצב שבו השרת לא זמין, מוצגות למשתמש כהודעה ברורה בעברית.

## מבנה משימה

| שדה            | טיפוס      | הערות                                                            |
| -------------- | ---------- | ---------------------------------------------------------------- |
| `id`           | מספר       | נוצר אוטומטית                                                    |
| `title`        | טקסט       | חובה, עד 100 תווים                                               |
| `description`  | טקסט       | אופציונלי                                                        |
| `status`       | טקסט       | אחד מהערכים `ToDo`, `InProgress`, `Done`. ברירת המחדל היא `ToDo` |
| `priority`     | טקסט       | אחד מהערכים `Low`, `Medium`, `High`. ברירת המחדל היא `Medium`    |
| `dueDate`      | תאריך      | אופציונלי                                                        |
| `categoryId`   | מספר       | אופציונלי, חייב להיות מזהה של קטגוריה קיימת                      |
| `categoryName` | טקסט       | מוחזר בתשובות בלבד                                               |
| `createdAt`    | תאריך ושעה | נקבע בשרת בעת היצירה                                             |
| `updatedAt`    | תאריך ושעה | מתעדכן בשרת בכל שינוי                                            |

## נקודות הקצה של ה-API

| פעולה            | שיטה וכתובת                    | תשובה תקינה |
| ---------------- | ------------------------------ | ----------- |
| רשימת קטגוריות   | `GET /api/categories`          | 200         |
| רשימת משימות     | `GET /api/tasks`               | 200         |
| משימה לפי מזהה   | `GET /api/tasks/{id}`          | 200         |
| יצירת משימה      | `POST /api/tasks`              | 201         |
| עדכון משימה מלא  | `PUT /api/tasks/{id}`          | 200         |
| שינוי סטטוס בלבד | `PATCH /api/tasks/{id}/status` | 200         |
| מחיקת משימה      | `DELETE /api/tasks/{id}`       | 204         |

### רשימת קטגוריות

`GET /api/categories`

מחזירה את כל הקטגוריות הקבועות במערכת.

```json
[
  { "id": 1, "name": "לימודים" },
  { "id": 2, "name": "עבודה" },
  { "id": 3, "name": "אישי" },
  { "id": 4, "name": "בית" }
]
```

### רשימת משימות

`GET /api/tasks`

מחזירה את כל המשימות, ממוינות לפי מזהה. אפשר להוסיף לכתובת שני פרמטרים אופציונליים, כל אחד לחוד או שניהם ביחד:

| פרמטר    | תיאור                        | דוגמה                    |
| -------- | ---------------------------- | ------------------------ |
| `status` | מחזיר רק משימות בסטטוס הזה   | `/api/tasks?status=Done` |
| `search` | מחפש את הטקסט בכותרת ובתיאור | `/api/tasks?search=מבחן` |

שגיאות אפשריות: 400 כשערך הסטטוס לא קיים.

### משימה לפי מזהה

`GET /api/tasks/{id}`

מחזירה משימה אחת:

```json
{
  "id": 1,
  "title": "להגיש את מסמך האפיון",
  "description": "לסיים את כל הסעיפים ולהוסיף סקיצות",
  "status": "ToDo",
  "priority": "High",
  "dueDate": "2026-11-15T00:00:00",
  "categoryId": 1,
  "categoryName": "לימודים",
  "createdAt": "2026-11-10T10:35:23",
  "updatedAt": "2026-11-10T10:35:23"
}
```

שגיאות אפשריות: 404 כשאין משימה עם המזהה הזה.

### יצירת משימה

`POST /api/tasks`

גוף הבקשה. רק השדה `title` הוא חובה:

```json
{
  "title": "להגיש את מסמך האפיון",
  "description": "לסיים את כל הסעיפים ולהוסיף סקיצות",
  "status": "ToDo",
  "priority": "High",
  "dueDate": "2026-11-15",
  "categoryId": 1
}
```

מחזירה 201 עם המשימה שנוצרה, כולל המזהה שלה, ובכותרת `Location` את הכתובת של המשימה החדשה.

שגיאות אפשריות: 400 כשהכותרת ריקה או ארוכה מ-100 תווים, כשהסטטוס או העדיפות לא חוקיים, או כשהקטגוריה לא קיימת.

### עדכון משימה מלא

`PUT /api/tasks/{id}`

גוף הבקשה זהה ליצירה. העדכון מחליף את כל השדות, ולכן צריך לשלוח את כולם: שדה אופציונלי שלא נשלח יימחק.

מחזירה 200 עם המשימה המעודכנת.

שגיאות אפשריות: 404 כשהמשימה לא קיימת, ו-400 מאותן סיבות כמו ביצירה.

### שינוי סטטוס בלבד

`PATCH /api/tasks/{id}/status`

משמשת בעיקר לסימון משימה כהושלמה, בלי לשלוח את כל המשימה:

```json
{
  "status": "Done"
}
```

מחזירה 200 עם המשימה המעודכנת.

שגיאות אפשריות: 404 כשהמשימה לא קיימת, ו-400 כשהסטטוס חסר או לא חוקי.

### מחיקת משימה

`DELETE /api/tasks/{id}`

מחזירה 204, בלי גוף תשובה.

שגיאות אפשריות: 404 כשהמשימה לא קיימת.

## פורמט השגיאות

השרת מחזיר שגיאות בשני מבנים, לפי סוג השגיאה. צד הלקוח יודע לקרוא את שניהם ולהציג את ההודעה למשתמש.

כשהבדיקה האוטומטית של הנתונים נכשלת, למשל בכותרת ריקה, חוזר מבנה סטנדרטי בשם ProblemDetails, ובשדה `errors` מפורט מה לא תקין בכל שדה:

```json
{
  "title": "One or more validation errors occurred.",
  "status": 400,
  "errors": {
    "Title": ["יש להזין כותרת למשימה"]
  }
}
```

בשגיאות שהשרת בודק בעצמו, כמו משימה שלא נמצאה או קטגוריה שלא קיימת, חוזר אובייקט עם הודעה אחת:

```json
{
  "message": "משימה 999 לא נמצאה"
}
```

## בדיקות

הקובץ `TaskManager.postman_collection.json` מכיל את כל בדיקות ה-API: בדיקה לכל אחת מנקודות הקצה, ובדיקות למצבי שגיאה כמו כותרת ריקה, קטגוריה לא קיימת, סטטוס לא חוקי ועדכון של משימה שלא קיימת. כדי להריץ אותן, יש לייבא את הקובץ ל-Postman דרך Import, להפעיל את השרת ולהריץ את הבקשות.
